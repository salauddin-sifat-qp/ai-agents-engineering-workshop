Example 05 · the real one

edit_file — four rules

Read before write
Editing an unread file is editing a remembered file.
Exactly one match
Zero and many are different errors with different fixes.
Failed match is an error
Never a silent no-op. The worst case is the agent reasoning on from a fix that never landed.
Return a diff
A human must be able to review it without opening the file.

And that's the simple version

What pi's edit tool adds

Line endings
CRLF normalised before matching, restored on write.
Invisible BOM
Stripped before matching. The model can't see it.
Fuzzy fallback
Trailing spaces, smart quotes, Unicode dashes normalised if the exact match fails.
Many edits, one call
Each matched against the original file. No overlaps.
Per-file queue
Parallel edits to one file can't race.

Every line is a bug someone hit in production.

Example 06

Compaction

[system] [task] [..... summarised .....] [recent turns verbatim]
System + task stay verbatim
Lose the task and the agent forgets what it was doing.
Recent turns stay verbatim
That's where the live work is.
The middle gets summarised
That's where the bulk and the redundancy are.

"Recent" is a size, not only a count: one huge result kept verbatim and compaction fires again every turn.

Truncation deletes. Compaction remembers, in less space.
The bug everyone hits once

Orphaned tool results

assistant: tool_call  id=abc   <- cut by compaction
tool:      result     id=abc   <- now an orphan
                               -> provider rejects the whole request

Cut the middle out and you can strand a tool result whose call is gone. Most providers reject the entire request. Rule: never cut between a call and its results.

Persistence

Save every turn,
not at the end

.session/transcript.jsonl   # one message per line, appended, never rewritten
                            # compaction is an entry, not an overwrite

pnpm 06          # Ctrl-C partway through
pnpm 06:resume   # picks up mid-task
A session you can only resume after a clean exit is a session you cannot resume. Crashing is exactly when you want it.
Your own tool does the same

Open its session file

ls ~/.pi/agent/sessions/          # pi   (Claude Code: ~/.claude/projects/)
tail -n 3 <session>.jsonl | jq -c '{type, id, parentId}'
grep -c '"type":"compaction"' <session>.jsonl

One entry per line. Compaction is an entry, not an overwrite. Every entry has a parentId, so a session is a tree: that's why /tree and /fork can go back without losing anything.
