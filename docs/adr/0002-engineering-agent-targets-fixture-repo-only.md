# Engineering Agent operates only on a bundled Fixture Repo

The Engineering Agent's tools (search_code, read_file, list_files, run_tests, and from example 06 edit_file) always target a small, deliberately-crafted Fixture Repo bundled inside the workshop, never the workshop repo itself and never an attendee's own project. We considered pointing it at the workshop repo (more "meta") or letting attendees bring their own project (more "real"), but rejected both: self-targeting risks tool output changing as the workshop repo itself is edited, and bring-your-own-project makes agent behavior unpredictable across attendees, undermining the scripted failure/fix narrative in section 23. A fixed fixture gives every attendee an identical, deterministic target with a known failing test to find.

The fixture is themed as a small "Pokédex API" service purely for memorability. We considered replacing the tool set itself with theme-specific tools (e.g. `get_pokemon`, `check_battle_stats`), but rejected it: the audience is engineers who need transferable muscle memory on real code/test/git tools, and swapping those out for domain trivia tools would break that transfer. Theming is limited to the fixture's identity and bug story; the tools remain search_code, read_file, list_files, run_tests, edit_file against real code and real tests.
