Mental model

Agent ≠ LLM + prompt

An AI agent is a runtime that allows an LLM to operate in an environment through controlled actions.

The execution boundary

Model requests.
Application decides.

Model
Requests a tool call. Never runs it.
Application
Validates, classifies, maybe asks a human.
Tool
Runs. Returns a result.
Model
Receives the result, decides what's next.

A choice, not a default

Workflow vs. agent

A deterministic workflow has a fixed sequence of steps. An agent decides its own sequence of tool calls. Use the simplest one that solves the task, an agent is not automatically the right answer.

MCP architecture

Two transports,
same server

stdio
Client spawns the server as a child process, no networking.
HTTP
Server runs standalone on a port, client connects remotely.

Stateless HTTP transports need a fresh transport per request, a documented SDK constraint, not an implementation detail you can skip.

The most important slide in this section

When NOT to use
multi-agent

Multi-agent is not automatically better.

More tokens, more latency, more failure surface. Reach for it only when the task genuinely decomposes into independent or adversarial sub-tasks.

Final mental model

Agency, not just
intelligence.

The model provides intelligence; the runtime provides agency. The tools provide capabilities; protocols provide interoperability; state provides continuity; policies provide control; evaluation provides confidence.
